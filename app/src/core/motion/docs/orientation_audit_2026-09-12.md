# 姿态包络与法向保真优化核查 — 2026-09-12

结论：保留“候选姿态 + 全路径逆解分支搜索”的框架是合理的，但当前实现不能保证“在指定包络内尽量贴近原法向，并通过姿态调整挽救无解点”。本次在两组指定数据上确认了目标优先级不符、候选遗漏、零包络失效和搜索/验证插补不一致等问题。当前默认优化能让两组数据通过现有验证器，这不等于已经实现了上述优化目标。

本报告分析当前工作区（含任务开始前已有的未提交修改）。重新编译至 `/tmp/aisprayer-motion-analysis-build`，没有覆盖运行中的二进制、生产源码、配置或原始模板文件，没有调用机械臂。完整实验命令、指标及输入/关键源码 SHA-256 保存在同目录 `orientation_audit_2026-09-12_results.json`。临时输出和日志在 `/tmp/aisprayer-orientation-audit`。

## 需求的统一定义

用户明确要求同时支持两种包络：

| 模式 | 包络中心 | 要尽量保持的方向 |
| --- | --- | --- |
| 逐点原姿态 `raw` | 当前航点原始旋转矩阵 R₀ᵢ | 当前点原始喷枪方向 n₀ᵢ |
| 统一参考姿态 `config/home/live` | 整条路径共用的旋转矩阵 Rref | 仍然是当前点原始喷枪方向 n₀ᵢ |

两种模式只改变约束中心，不能把统一参考姿态当作法向保真目标。指定包络之外的姿态始终禁止；包络内允许调整，不代表每个点都必须偏转。

当前包络定义为相对旋转 `EulerXYZ(Ranchorᵀ R)` 的三分量范围，不是基座系 Rx/Ry/Rz 的直接加减，也不是圆锥半角。`[10,10,180]` 在逐点模式下容许的最大法向夹角约为 `acos(cos(10°) cos(10°)) = 14.11°`，不能解释成“偏离法向最多 10°”。本报告所有包络检查沿用现有定义，避免暗中改变用户参数语义。

法向保真应直接衡量 `θᵢ = acos(clamp((Rᵢ ez) · n₀ᵢ, -1, 1))`。这两组数据中原始 Tool Z 与 `-surface_normal_base` 的最大差分别仅 0.012°、0.006°，所以本次以原始 Tool Z 为基准；表面外法向需要取反。绕工具自身 Z 轴旋转不改变这个方向，但扇形喷嘴的喷幅方向仍需服从自旋包络。

## 实测结果

所有实验使用当前 URDF 中的 CR5 和 `gripper_tip_link`，名义速度 150 mm/s、密集检查步长 2 mm。**当前配置开启了奇异附近降速**，因此下列 PASS 不是全程恒定 150 mm/s 的证明。例如默认逐点优化输出的最低建议航点速度分别为 30.0、62.8 mm/s。所有完整路径实验保持 TCP 航点位置不变。

| `092632`，14 点、598 插值点 | 当前默认优化 | PASS | 2.688° / 1.505° | 80.9°/s |

“约 0°”的自旋实验在内存中保持法向不变，落盘后因欧拉角保留两位小数产生小于 0.009° 的误差。包络审计对落盘角使用 0.02° 数值容差；这是诊断容差，不是额外工艺授权。

`092632` 是直接反例：不修改任何姿态，现有优化器仍可通过选择正确逆解分支得到 PASS；默认结果反而无必要地偏转法向。原路径默认验证失败，不能据此断言原姿态几何不可达；默认起始分支与全路径搜索选出的分支不同。报表的 `unreachable_count` 还包含分支跳变和关节越限，不能直接当作“无 IK 的点数”。

对 `104336` 逐点调用当前解析 IK：只有数组位置 50、文件 `index: 51` 的原姿态完全没有 IK。该点保持 TCP 位置和法向不变，仅绕工具自身 Z 轴旋转 **−13°**，就得到 **2 个限位内且非奇异的解**（按 1° 间隔由小到大扫描找到的结果，不是连续域最小自旋角证明）。这证实姿态调整能够挽救该点；但整条路径的自旋搜索仍可能失败，说明“点有解”和“整条轨迹连续可执行”必须分别验证。

额外尝试了较小倾角网格、包含零点的偶数网格和完整自旋网格。部分结果在搜索阶段有解，终校却出现跳变或超速；没有证据证明 `104336` 的 7.073° 已是最小必要偏差，也不能把缩小网格或扩大自旋范围当成现成修复。

## 源码原因与需要修正的行为

1. **原姿态不在候选集。** `configs/aisprayer_config.yaml:103` 的 X/Y 网格是 `[-15,15,2]`，经 `conventions.hpp:159` 展开为 −15、−13、…、−1、1、…、15，没有 0。`optimizer.cpp:173` 只组合这些网格姿态，没有额外注入原姿态。因此原姿态及零倾角自旋族都被遗漏。正常非零 raw 包络下，当前两条轴的最小绝对倾角都是 1°，候选最小指向偏差约 1.414°。

2. **目标函数和阶梯比较器都允许牺牲法向。** `optimizer.cpp:191` 使用相对欧拉角加权平方，权重 `[1,1,0.01]`，随后直接加上关节运动代价。这只是倾向于少偏转，并非优先保证最接近法向。`optimizer.cpp:793` 又把峰值速度排在最大法向偏差之前。应当先满足运动学可行性和速度要求，再以实际法向夹角择优，最后比较多余自旋、关节平滑度和安全余量。

3. **包络比搜索范围大；回退没有扩展姿态域。** 当前 Z 允许 ±180°，网格只搜索 ±30°。`optimizer.cpp:597` 的 fallback 仅恢复当前层已经算出的全量候选，没有增加新姿态，也没有恢复上一层被 beam 删除的分支。没有候选时直接抛“包络内无解”，其实只能说明现有采样没有找到解。固定参考模式还会把原姿态附近网格投影到包络的一小片区域，不能视为完整覆盖包络。

4. **逐分量裁剪不是“距离原法向最近”的投影。** `optimizer.cpp:105` 把相对欧拉角逐分量截断，只能提供一个包络内姿态。固定参考模式尤其应区分“最近的允许枪轴方向”和“围绕该方向选择自旋角”。矩阵/四元数应作为内部方向计算表示；保留现有欧拉包络语义时，候选仍需用同一包络判据检查，不能直接更换参数化却沿用相同数值。

5. **零包络边界失效。** `optimizer.cpp:465` 只在 raw 容差范数大于零时建立局部锚点。`[0,0,0]` 因而绕过全部裁剪。用 `104336` 的第 51 点复现：请求零包络仍返回 PASS，相对欧拉偏转的绝对值为 `[0.997°,1.001°,14.996°]`，方向偏差 1.413°。零包络应严格保留原姿态；该点应明确报告原姿态不可达，不能越界救点。

6. **搜索与终校使用不同的运动段。** `optimizer.cpp:310` 先把两端 TCP 转为法兰，以法兰位置直线插补，并按法兰段长折算时间；`segment.cpp:116` 的终校插补则沿 TCP 直线，以 TCP 段长计时，再逐点转换为法兰。约 252 mm 的偏置工具发生转动时，两者通常不同。另外，搜索速度检查使用端点关节差/整段时间（`optimizer.cpp:362`），终校检查密集步速度，所以前者不能约束段内峰值。必须复用同一 TCP 插补、工具变换和逐步速度判据，并在终校失败时反馈到搜索，不应仅切换更紧包络碰碰运气。

当前验证器没有接收姿态锚点与包络，不能独立验收整个连续段的包络约束。未来还应检查插值姿态：固定模式用固定中心；逐点模式需要明确定义段内参考法向/姿态的插值规则。仅两端合法不等于整个插值段合法。

## 建议采用的优化流程

保留已有分层候选图，但把约束、目标和搜索覆盖分开：

1. **硬约束先固定。** TCP 航点位置、用户选定的包络、关节限位、奇异风险、连续分支和允许速度都明确约束。严格处理零包络。是否允许降速应作为明确的工艺策略，不能把降速贡献归因于姿态优化。
2. **建立最少偏转的基础候选。** raw 模式先放入完整原姿态，再枚举包络允许的零倾角自旋；固定模式先寻找包络内最贴近当前原法向的方向，再枚举满足包络的自旋。保留多个 IK 分支。
3. **需要时才扩大倾角搜索。** 在用户包络内，由小偏差向大偏差扩展，并细化失败点周围的方向和自旋采样。保留零点、边界点和先前找到的有效候选，避免网格变化让可行解消失。点/段失败时，重新搜索包含前后邻点的局部窗口，恢复相关被剪枝分支。
4. **以法向保真为主要质量目标。** 推荐先最小化全路径最大法向偏差，再最小化累计平方法向偏差，最后优化关节运动和自旋平滑。可用法向误差上限的递进搜索配合分层图搜索实现，避免凭权重比例交换工艺质量。这个优先级应在两种包络模式中完全一致。
5. **统一插补验证并闭环重搜。** 候选边和终校复用同一 TCP 运动模型。密集检查失败后，把问题段、IK 分支和姿态反馈到局部重搜；序列化后按保存的起始分支再次验证，并复核包络。
6. **诚实报告求解边界。** 有限采样和 beam 搜索通常不是连续域完备算法。报告要区分“原姿态无 IK”“采样预算内未找到解”“点有解但段不连续”“终校超速”等，给出实际搜索范围、分辨率和失败位置。若用户包络内确实没有可行姿态，任何算法都不能保证救活该点，应返回明确不可行结果，不能自动越界。

在固定 TCP 位置下改变枪轴也会改变喷射落点。以局部平面、法向喷距 150 mm 为近似，7° 倾斜会产生约 `150 tan(7°) ≈ 18.4 mm` 的横向偏移。因此“运动学通过”之外，后续还需确认工艺究竟固定 TCP 轨迹，还是固定表面命中点/喷距；本次实验遵循现有代码，保持 TCP 航点位置不变，没有修改路径几何。

上述方向与工业轨迹规划中对工具轴旋转冗余的建模一致，可参考 ROS-Industrial 的 [Descartes AxialSymmetricPt](https://docs.ros.org/en/hydro/api/descartes_trajectory/html/classdescartes__trajectory_1_1AxialSymmetricPt.html)。姿态误差参数化的区别和欧拉角限制可参考 [MoveIt OrientationConstraint](https://moveit.picknik.ai/main/api/html/classkinematic__constraints_1_1OrientationConstraint.html)。这些资料支持建模思路，本报告的具体故障与数值来自本项目源码和本次实测。

## 验收基准与复现

后续修改至少应通过：两种包络模式；零包络；原姿态已经可行时不增加法向误差；第 51 点能在保持法向的情况下找到有效自旋；包络边界附近候选细化；局部点可达但相邻段不可达时回溯；保存后仍满足约束；任何失败结果不得授权执行。已有 `test_kinematics` 本次通过。这里的 PASS 均限于项目现有运动学验证器，尚未验证实机控制器插补、碰撞或完整动力学。
